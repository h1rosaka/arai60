- step1
    ```py
    """
    connected_nodes[[], []]

    要素(x,y)
    全てのsetに関して確認
        
        xが入ってるの見つけた場合
            yが他のsetにないか確認
                yあった場合、
                    set同士の合体
                yなかった場合、yを足す

        xがどこにも入ってなかったら、
            yが入ってるか確認
                yがあった場合
                    そこにxを足す
                yなかった場合
                    新たなset作って、その要素入れる

    """

    # [0,1][1,2]
    class Solution:
        def countComponents(self, n: int, edges: List[List[int]]) -> int:
            connected_sets = []
            unseen_nums = set([num for num in range(n)])
            def serach_in_connected_sets(target:int) -> int:
                for i in range(len(connected_sets)):
                    if target in connected_sets[i]:
                        return i
                return -1 

            for edge in edges:
                # unseen_numsからの除去
                for num in edge:
                    if num in unseen_nums:
                        unseen_nums.remove(num)
                x, y = edge
                set_num_x = serach_in_connected_sets(x)
                # xが入ってるの見つけた場合
                if set_num_x != -1:
                    # yが他のsetにないか確認
                    set_num_y = serach_in_connected_sets(y)
                    # yあった場合、setの合体
                    if set_num_y != -1:
                        if set_num_x != set_num_y:# ここ忘れてた。残り1個だと、消えてしまう
                            connected_sets[set_num_x] = connected_sets[set_num_x] | connected_sets[set_num_y]
                            connected_sets.pop(set_num_y)
                            print("after_merged", connected_sets)
                    # yなかった場合、yを足す 
                    else:
                        connected_sets[set_num_x].add(y)
                        print("after_added", connected_sets)
                # xがどこにも入ってなかった場合
                else:
                    # yが他のsetにないか確認
                    set_num_y = serach_in_connected_sets(y)
                    # yあった場合、そこにxを足す
                    if set_num_y != -1:
                        connected_sets[set_num_y].add(x)
                        print("after_added", connected_sets)

                    # yなかった場合、新たなsetとして足す
                    else:
                        connected_sets.append({x, y})

            return len(connected_sets) + len(unseen_nums)
    ```

- setのさまざまな処理
    - https://docs.python.org/ja/3.13/library/stdtypes.html#set
- set | other
    - set と全ての other の要素からなる新しい集合を返します。
- set & other
    - set と全ての other に共通する要素を持つ、新しい集合を返します。
- set <= other
    - set の全ての要素が other に含まれるか判定します。
- set - other
    - set と other のいずれか一方だけに含まれる要素を持つ新しい集合を返します。
- set.add()/ set.remove()/ set.discard()
    - removeはないとKeyErrorだが、discardはエラー出さない
- set.pop()
    - 任意の要素を取り除いた上で、それを返す。

計算量
- nodeの数がN, edgeの数がMだったとき、
    - for ループが M 回
        - serach_in_connected_sets(x)が、connected_setの数だけ→最大N
        - serach_in_connected_sets(y)が、connected_setの数だけ→最大N
        - |演算　両方からのコピーで合体　→最大N　
        - pop connected_setsの中身の数分　→　最大N
    - O(MN)の時間計算量

    - https://ja.wikipedia.org/wiki/%E9%9A%A3%E6%8E%A5%E3%83%AA%E3%82%B9%E3%83%88
    - edges = [[0,1],[1,2]] みたいな入力を、下記のような「隣接リスト」に変換
    - ```
        0: [1]
        1: [0,2]
        2: [1]
      ```
    - リストの上から深さ優先で繋げていく。すでに見た数字はseenで管理しておいて、あとで順番が回ってきたらskipする
    - 最初の島を作ってしまってから、次の島に移るイメージ
        - それぞれの島がどういうものかすら管理する必要はなく、「このマス(ノード)は踏破済みか」だけ管理
    - 全てのノードを1回は確認するので、O(N)かかる。また、それぞれのノードに対して、連結を見に行くのは1つのedgeに対して2回確認が入るので2Eで、O(E)
    - O(N+E)
    - Step1のやり方だと、edge(全部でO(E)個)が1つ来るたびに、入ってないもの含め全ての島(O(N)個)確認して、、と非効率
    - 隣接リスト作成コスト: O(E)


- DFS
    ```py
    class Solution:
        def countComponents(self, n: int, edges: List[List[int]]) -> int:
            adj = defaultdict(list)
            for node1, node2 in edges:
                adj[node1].append(node2)
                adj[node2].append(node1)

            seen = set()
            def visit_adjacent_nodes(node):
                if node in seen:
                    return
                seen.add(node)
                for adj_node in adj[node]:
                    visit_adjacent_nodes(adj_node)

            num_connected_components = 0
            for node in range(n):
                if node not in seen:
                    num_connected_components += 1
                    visit_adjacent_nodes(node)

            return num_connected_components

    ```


- 再帰ではなくループでDFS

    class Solution:
        def countComponents(self, n: int, edges: List[List[int]]) -> int:

            for node1, node2 in edges:
                adj[node1].append(node2)

            seen = set()

            candidates = []
            for node in range(n):
                if node in seen:
                    continue
                num_connected_components += 1
                candidates.append(node)            
                while candidates:
                    node = candidates.pop()
                    if node in seen:
                        continue
                    seen.add(node)
                    for adj_node in adj[node]:
                        candidates.append(adj_node)

            return num_connected_components
    ```

union find
- https://algo-method.com/descriptions/133

- イメージ: 最初は全員一匹狼だったものが、傘下に入りながら組になっていく。
- 方針:最初は全てバラバラで、edgeを一つ一つ見ながら連結していき、グループ数カウントを減らしていく
    - 最初は全員1匹狼で親分。組の数=人数。
    - edgeが一つ来るたびに、そこに出てくる2者が同じ組になるように、組同士の合併が起きる。
    - 組の合併は親分同士で親子になる形で実施
    - どちらが親になるかは、組のrank(歴史?家系図?)が大きい方が親になるようにする。
        - →こうすると、効率が良い
    - 合併が完了したら、組の数カウントを一つ減らす
    - 全てのedgeを見終わったら、組の数カウントを返す。

- 実現のための2つの重要な関数
    - union(x,y)
        - xとyの所属する組の親を調べて、別人だったら合併
            - 合併時、rank見て、歴史の長い組の親が新しいマージ後の組織の親に
            - 実装としてはparent[x]というリストで管理

    - find(x)
        - xの親分が誰か返す。
            - パス圧縮も実施

- 2つの工夫により、union()もfind()もほぼO(1)でできる
    - パス圧縮
        - 親子関係のパスを圧縮し、「孫,ひ孫...を全て一代目の親分の子に」という処理を適宜パス見る度に実施

    - union by rank
        - 前提: グループ同士のマージ(union)は、それぞれの親同士が親子になる形で実現
        - 方針：findが楽なように、高さをなるべく抑えたい。
        - ランクが高い(歴史が長い)組の親分を、合併後も親分とする。
            - どちらが親になると木が伸びないか考える
            - 方針：長く続いてる家族(組?グループ?)を尊重する。
            - 100代続く家族の傘下に、1代目の成り上がりが入っても、全体の家系図は伸びない
            - 一方、1代目の成り上がりに100代続く家族が入ると、高さが101になる。
        - 家系図の高さが伸びるのは、自分と同じrankの組みを吸収した時だけ。(自分より弱い奴を吸収してもランクは増えない)
            - 自分の組の方が相手の組より高いとき　→ 自分の組の高さのまま
            - 相手の組の方が自分の組より高いとき　→ 自分の組は消滅
            - 自分の組と相手の組が同じ高さのとき　　 → 高さが1つ増える。 

        - イメージ: 
            どれだけ自分と同じ強さの奴を傘下に入れることができたか、で格(rank/家系図の長さ)が決まり、格の高い組の親分が合併時にはまた親分になる。

        - パス圧縮したら家系図崩壊して、rankも壊れてしまうのでは？
            - パス圧縮後のrank: 「現在の高さ」ではなく、「過去最大でこれくらいの高さになり得た」というポテンシャルのようなもの
            - 運用の割り切り: 正確さを求めて計算を重くするより、多少不正確でも「高い方を親にする」という指針を維持する方が、トータルの効率が良いという設計判断

            - 1. 正確な高さを再計算するコストが高すぎる
                - パス圧縮のたびに計算し直すのはコストが高い
            - 2. 「だいたい」なのだが、それでも十分に高さが抑えられる
                - union by rank
                    - これで、木の高さがO(logN)以下に抑えられる(例え、途中で高さの高い方を下につけてしまったとしても)
                    - 証明: 
                        - 高さが h の木を作るためには、高さが h−1 の木を 2 つ用意する必要がある
                            - 高さ 0 の木は少なくとも 1 つのノードを持つ
                            - 高さ 1 の木は少なくとも 2 つのノードを持つ
                            - 高さ 2 の木は少なくとも 4 つのノードを持つ
                            - ...
                            - 高さ h の木は少なくとも 2^h のノードを持つ
                                - →したがって、ノード数Nの時の木の高さは
                                    - 2^h = N
                                    - h = logN となって、logN以下であることがわかる

- union find
    ```py
    class Solution:
        def countComponents(self, n, edges):
            parent = list(range(n))
            rank = [0] * n
            def find(x:int) -> int:
                if parent[x] != x:
                    parent[x] = find(parent[x])
                return parent[x]     

            def union(x:int, y:int) -> bool:
                root_x = find(x)
                root_y = find(y)
                if root_x == root_y:
                    return False
                
                if rank[root_x] > rank[root_y]:
                    parent[root_y] = root_x
                elif rank[root_y] > rank[root_x]:
                    parent[root_x] = root_y
                else:
                    parent[root_y] = root_x
                    rank[x] += 1
                return True

            num_connected_components = n
            for x, y in edges:
                if union(x, y):
                    num_connected_components -= 1

            return num_connected_components

    ```

- ちなみに、結局UnionFindにしても、edgeの数だけループするので、O(E)で、そこまで速くならない
- どういう時にunion findは便利か
    - is_connected(u, v) といったクエリがある
        - DFSだと、グラフを探索する必要がある
    - 辺がどんどん追加され、その度に連結か知りたい、など
        - DFSだと、木の大部分の更新が必要。UnionFindならほんの一部だけ。
