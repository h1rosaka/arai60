# STEP 1 自力で解く。

- 所要時間
    - 思い付かず、答えを見た。
- 計算量
    - 時間
        - O(N)
        - node_valsへの追加がO(N)、取り出す作業もO(N)なので。
    - 空間
        - O(N)
        - node_valsがO(N)。新しく作った連結リストもO(N)

```python
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        node_vals = []
        node = head
        while node:
            node_vals.append(node.val)
            node = node.next

        dummy_head = ListNode()
        node = dummy_head
        for i in range(len(node_vals)):
            node.next = ListNode(node_vals.pop())
            node = node.next

        return dummy_head.next
```

- stack
    - node_valではなくnode自体を保存して、古いつながりを切りつつ連結してる。
    - この場合の方が、step1の解放と違って連結リストは一つしかできないので、メモリの効率は少し良さそう。(O(N)には変わりなしだが。)
    - ただし連結を切ったり付けたりがstep1より複雑で、うっかりバグをつくりそうな気もするが、私が linked list に慣れてないだけなのだろうか


- recursive
    - 参考にしつつ少し変更して書いた
    - 時間: O(N)
        - O(1)のループが一回
    - 空間: O(N)
        - 再帰のスタックがN回分でO(N)

```py
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if head is None:
            return None
        def reverse(prev_node, node):
            if node.next is None:
                node.next = prev_node
                return node
            next_node = node.next
            node.next = prev_node
            return reverse(node, next_node)
        return reverse(None, head)

```
- iterative
    - 再帰とすごく似ている
    - 参考にしつつ微調整
    - 時間:O(N)
        - O(1)のループが一回
    - 空間: O(1)
        - 再帰のスタックがないので。
```py
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        node = head
        prev_node = None
        while node:
            tmp = node.next
            node.next = prev_node
            prev_node = node
            node = tmp
        return prev_node
```
